# 专题｜前后端数据流与易混概念

> 适合在学完 MVC、HTTP、JSON、HTML/CSS 与 TypeScript 后阅读。  
> 目标：把零散概念放回同一条请求链路，并纠正常见但过度简化的说法。

[学习首页](../README.md) · [MVC 分层架构](./01-MVC分层架构.md) · [HTTP 与 HTTPS](./02-HTTP与HTTPS.md) · [JSON 数据格式](./03-JSON数据格式.md)

## 1. 先记住这一条完整数据流

以“创建 Todo”为例：

```text
Vue 页面输入
    ↓
TypeScript TodoCreate
    ↓ Axios / fetch 序列化
HTTP POST + JSON
    ↓
FastAPI Router
    ↓ Pydantic TodoCreate 校验
Service 执行业务规则
    ↓
SQLAlchemy Todo ORM 对象
    ↓ 生成并执行参数化 SQL
PostgreSQL todos 表
    ↓
SQLAlchemy 对象
    ↓ Pydantic TodoOut 序列化
HTTP 201 + JSON
    ↓
TypeScript Todo
    ↓
Vue 更新页面
```

这些概念不是相互替代，而是在不同边界承担不同职责。

## 2. 一份 Todo 为什么需要多个“模型”

同一个业务对象在不同阶段需要不同形状：

| 层次 | 典型名称 | 主要职责 | 是否在运行时校验 |
| --- | --- | --- | --- |
| 前端类型 | `TodoCreate`、`Todo` interface | 编辑器提示和编译期检查 | 否 |
| API Schema | Pydantic `TodoCreate`、`TodoOut` | 请求校验、响应序列化、OpenAPI | 是 |
| 业务对象 | Domain Model / dataclass，可选 | 表达业务状态和规则 | 取决于实现 |
| ORM Model | SQLAlchemy `Todo` | 映射数据库表、关系和持久化 | 负责 ORM 映射，不等同于 API 校验 |
| 数据库表 | `todos` | 最终保存数据和执行约束 | 是，依靠字段和约束 |

它们都可能包含 title，但并不代表应该合并成一个类型。

## 3. schemas 文件夹究竟是什么

FastAPI 项目通常使用复数 `schemas/`，而不是 `scheme/`。这里一般存放 Pydantic 模型：

```text
app/
├─ api/           HTTP 路由
├─ schemas/       API 请求与响应契约
├─ services/      业务规则
├─ models/        SQLAlchemy ORM 模型
└─ db/            数据库连接和会话
```

常见 Schema：

```python
from pydantic import BaseModel, ConfigDict, Field


class TodoCreate(BaseModel):
    title: str = Field(min_length=1, max_length=100)


class TodoUpdate(BaseModel):
    title: str | None = Field(default=None, min_length=1, max_length=100)
    completed: bool | None = None


class TodoOut(BaseModel):
    model_config = ConfigDict(from_attributes=True)

    id: int
    title: str
    completed: bool
```

Schema 的作用不只是“创建新类型”，还包括：

- 校验请求字段和约束；
- 把输入转换为 Python 对象；
- 控制允许返回的字段；
- 把 ORM 等对象序列化为 JSON；
- 生成 JSON Schema 和 OpenAPI 文档。

## 4. Schema 能不能在函数之间传递

可以，而且在小型 FastAPI 项目中很常见：

```python
@router.post("/todos", response_model=TodoOut, status_code=201)
async def create_todo_endpoint(data: TodoCreate):
    return await todo_service.create_todo(data)
```

```python
async def create_todo(data: TodoCreate) -> Todo:
    todo = Todo(title=data.title)
    # 保存数据库……
    return todo
```

但不要推导出“所有内部函数都必须使用 API Schema”。

如果业务复杂，Service 可以使用独立的命令对象或领域对象，避免核心业务长期依赖 HTTP 接口形状：

```python
from dataclasses import dataclass


@dataclass(frozen=True)
class CreateTodoCommand:
    owner_id: int
    title: str
```

实用原则：

- 小项目：Router 把 Pydantic Schema 直接传给 Service，简单清楚；
- 复杂项目：在边界完成转换，让业务层依赖稳定的内部模型；
- 不要为了“分层”在每层创建内容完全相同、只负责原样转发的类型。

## 5. SQLAlchemy 是什么

SQLAlchemy 是 Python 的数据库工具集和 ORM。ORM 把 Python 类与关系型数据库表建立映射：

```python
from sqlalchemy.orm import DeclarativeBase, Mapped, mapped_column


class Base(DeclarativeBase):
    pass


class Todo(Base):
    __tablename__ = "todos"

    id: Mapped[int] = mapped_column(primary_key=True)
    title: Mapped[str]
    completed: Mapped[bool] = mapped_column(default=False)
```

对应关系：

```text
Todo 类          ↔ todos 表
Todo 对象        ↔ 一行记录
对象字段          ↔ 表字段
relationship     ↔ 表之间的关系
```

“使用 ORM 就不用懂 SQL”是错误理解。SQLAlchemy 会生成 SQL，但开发者仍需理解：

- 查询与 JOIN；
- 索引；
- 事务；
- N+1 查询；
- 约束；
- 执行计划。

ORM 是更安全、可组合的数据库访问方式，不是 SQL 知识的替代品。

## 6. ORM Model 与 Pydantic Schema 的区别

```text
SQLAlchemy Model
├─ 映射表名和字段
├─ 建立主键、外键和关系
├─ 参与查询与事务
└─ 负责持久化

Pydantic Schema
├─ 描述请求和响应形状
├─ 校验字符串长度、数字范围等
├─ 过滤不允许暴露的字段
└─ 生成接口文档
```

假设数据库 User 包含：

```text
id
username
password_hash
is_admin
created_at
```

公开响应可以只有：

```python
class UserOut(BaseModel):
    id: int
    username: str
```

数据库有字段，不代表 API 应该返回它。尤其不能把 password_hash 等内部字段直接序列化给前端。

## 7. 前端 TypeScript interface 的位置

```ts
export interface TodoCreate {
  title: string
}

export interface Todo {
  id: number
  title: string
  completed: boolean
}
```

它描述前端相信接口提供的数据结构，带来：

- 自动补全；
- 编译期字段检查；
- 重构辅助；
- 函数签名和组件 Props 约束。

但 interface 编译后会消失：

```ts
const todo = (await response.json()) as Todo
```

这句不会验证 JSON。它只是让编译器相信开发者的判断。

可靠做法是：

```text
后端 Pydantic 校验和过滤响应
        +
OpenAPI 描述唯一接口契约
        +
前端从契约生成或同步类型
        +
不可信外部数据在前端运行时再次校验
```

## 8. 前后端字段为什么可能不一致

后端 Python 常使用 snake_case：

```json
{
  "created_at": "2026-09-19T03:00:00Z"
}
```

前端 TypeScript 常使用 camelCase：

```ts
interface Todo {
  createdAt: string
}
```

团队有三种选择：

1. 前后端统一使用 snake_case；
2. API 对外统一使用 camelCase；
3. 在统一的 API 层进行一次转换。

不要在每个 Vue 组件里零散转换字段，否则很快会出现 `created_at`、`createdAt` 混用。

## 9. MVC 与前后端分离不是同一维度

一句话：

```text
MVC 讨论代码职责如何组织；
前后端分离讨论页面和 API 如何拆分、通信与部署。
```

它们可以同时存在，不是二选一。

## 10. 传统服务端 MVC

```text
浏览器请求 URL
      ↓
Controller
      ↓
Model / Service / Database
      ↓
Controller 选择 View 模板
      ↓
服务器渲染完整 HTML
      ↓
浏览器显示页面
```

View 在服务端，例如服务端模板。服务器通常直接返回 HTML。

## 11. SPA 前后端分离

```text
浏览器加载 Vue 应用
      ↓
Vue 负责界面和交互
      ↓ HTTP + JSON
FastAPI 提供 API
      ↓
Service + SQLAlchemy + Database
```

页面 View 主要运行在浏览器，后端通常返回 JSON。

“后端只剩 M + C”可以作为入门记忆，但不够准确：

- FastAPI 并不是要求严格 MVC 的框架；
- Pydantic 响应模型、序列化器或 Presenter 仍承担表现边界职责；
- Service、Repository、依赖注入、异常处理都超出原始 MVC 三部分；
- 现代 API 项目更适合直接称为分层架构。

课程采用的实用调用链：

```text
Router → Service → Model / Repository → Database
```

## 12. Vue 是否还需要 HTML 和 CSS

需要。Vue 单文件组件只是把相关结构、逻辑和样式组织在一个组件中：

```vue
<script setup lang="ts">
import { ref } from 'vue'

const count = ref(0)
</script>

<template>
  <button class="counter" type="button" @click="count++">
    点击次数：{{ count }}
  </button>
</template>

<style scoped>
.counter {
  padding: 0.75rem 1rem;
}
</style>
```

- template：以 HTML 为基础，增加 Vue 指令和组件能力；
- script：JavaScript / TypeScript 状态和行为；
- style：CSS，也可以使用预处理器；
- 浏览器最终接收标准 HTML、CSS 和 JavaScript，不直接理解 `.vue` 文件。

组件库能够减少重复 UI 工作，但不会让 HTML 语义、CSS 布局和无障碍知识失效。

## 13. JavaScript 与 TypeScript 的准确关系

```text
TypeScript = JavaScript 语法和运行时模型 + 静态类型系统 + 编译工具
```

| 对比 | JavaScript | TypeScript |
| --- | --- | --- |
| 类型检查 | 主要在运行时 | 编码和构建阶段静态检查 |
| 类型语法 | 没有 TS 类型语法，可使用 JSDoc 辅助 | interface、type、泛型等 |
| 执行 | 浏览器和 Node.js 直接执行 | 通常先移除类型并转换为 JS |
| 运行时 | JavaScript 运行时 | 仍然是 JavaScript 运行时 |
| 外部 JSON 校验 | 不会自动校验 | 也不会自动校验 |

需要修正两个过度简化的说法：

- JavaScript 的编辑器提示不一定很弱，JSDoc、类型声明和编辑器分析也能提供提示；
- “所有 JS 放进 TS 都绝对不报错”不严谨。语法大体兼容，但开启类型检查后，原有 JS 写法可能被报告类型问题。

TypeScript 的优势是提前暴露风险，不是保证程序没有 Bug。

## 14. JSON、FormData 和 urlencoded

### JSON

```http
Content-Type: application/json
```

适合结构化业务数据：

```json
{
  "title": "学习全栈",
  "completed": false
}
```

### multipart/form-data

适合文件与普通字段一起上传：

```ts
const data = new FormData()
data.append('name', '头像')
data.append('file', file)

await axios.post('/api/v1/files', data)
```

浏览器会自动生成 multipart boundary，通常不要手工设置 Content-Type。

### application/x-www-form-urlencoded

适合传统文本表单和部分 OAuth2 流程：

```text
username=alice&password=example
```

“上传文件必须使用 FormData”是常见 Web API 方案，但并非协议上的唯一方式。还可能使用原始二进制请求或对象存储预签名上传；在普通 Vue + FastAPI 表单中，multipart/form-data 最常见。

## 15. Path、Query、Header、Body 与 Form

| 位置 | 适合内容 | 示例 |
| --- | --- | --- |
| Path | 资源身份 | `/todos/42` |
| Query | 过滤、排序、分页 | `?completed=false&page=2` |
| Header | 认证、内容类型、追踪信息 | `Authorization: Bearer ...` |
| JSON Body | 结构化创建和更新数据 | `{"title":"学习"}` |
| Form | 文本表单字段 | `username=alice` |
| File | 上传文件 | multipart 中的 file part |

FastAPI 示例：

```python
from fastapi import FastAPI, File, Form, Header, UploadFile

app = FastAPI()


@app.post("/users/{user_id}/avatar")
async def upload_avatar(
    user_id: int,
    display_name: str = Form(),
    file: UploadFile = File(),
    trace_id: str | None = Header(default=None),
):
    return {
        "user_id": user_id,
        "display_name": display_name,
        "filename": file.filename,
        "trace_id": trace_id,
    }
```

## 16. FastAPI 校验失败为什么常见 422

FastAPI 使用 Pydantic 校验请求时，默认的请求验证错误通常返回：

```text
422 Unprocessable Content
```

例如接口要求：

```json
{
  "title": "学习 FastAPI"
}
```

却发送缺失必填字段或类型不符合约定的数据，就可能收到 422。

400 也可以用于通用错误请求，但不能简单断言“Pydantic 校验通常返回 400”。项目可以通过异常处理器统一改造错误响应，但必须在接口契约中说明。

## 17. 状态码速查

| 状态码 | 典型含义 | Todo 示例 |
| --- | --- | --- |
| 200 | 成功并返回内容 | 查询或更新成功 |
| 201 | 创建成功 | POST 创建 Todo |
| 204 | 成功但无响应体 | 删除成功 |
| 400 | 通用错误请求 | JSON 无法按约定处理 |
| 401 | 未通过认证 | Token 缺失或失效 |
| 403 | 已知身份但无权限 | 操作他人的 Todo |
| 404 | 路由或资源不存在 | Todo 42 不存在 |
| 405 | 方法不允许 | 对只支持 POST 的路径发 GET |
| 409 | 当前状态冲突 | 唯一字段重复 |
| 413 | 请求体过大 | 上传文件超过限制 |
| 415 | 媒体类型不支持 | 要求 JSON 却发送其他格式 |
| 422 | 字段验证失败 | Pydantic 请求校验失败 |
| 429 | 请求过于频繁 | 触发限流 |
| 500 | 未处理的服务端错误 | 程序异常 |
| 502 | 网关收到无效上游响应 | Nginx 无法正常访问应用 |
| 503 | 服务暂时不可用 | 维护或过载 |
| 504 | 网关等待上游超时 | 后端处理时间过长 |

不要把所有业务结果包装成 HTTP 200。HTTP 状态码负责传输层语义，响应体中的业务错误码可以提供更细分类别，二者可以配合。

## 18. curl 是什么

curl 是命令行网络客户端。它可以在没有 Vue 页面的情况下直接测试 FastAPI：

```text
Vue 表单 → Axios → HTTP → FastAPI
curl 命令 ─────────→ HTTP → FastAPI
```

Windows PowerShell 建议写 `curl.exe`，避免与旧版 PowerShell 别名混淆。

## 19. curl 测试 Todo CRUD

查询列表：

```powershell
curl.exe -i "http://127.0.0.1:8000/api/v1/todos?page=1&page_size=20"
```

创建：

```powershell
curl.exe -i `
  -X POST "http://127.0.0.1:8000/api/v1/todos" `
  -H "Content-Type: application/json" `
  -d '{"title":"学习 curl"}'
```

部分更新：

```powershell
curl.exe -i `
  -X PATCH "http://127.0.0.1:8000/api/v1/todos/42" `
  -H "Content-Type: application/json" `
  -d '{"completed":true}'
```

删除：

```powershell
curl.exe -i `
  -X DELETE "http://127.0.0.1:8000/api/v1/todos/42"
```

上传文件：

```powershell
curl.exe -i `
  -X POST "http://127.0.0.1:8000/api/v1/files" `
  -F "name=课程图片" `
  -F "file=@D:\images\course.png"
```

常用参数：

| 参数 | 作用 |
| --- | --- |
| `-i` | 输出响应头和响应体 |
| `-v` | 输出连接、TLS、请求和响应细节 |
| `-X` | 明确指定请求方法 |
| `-H` | 添加请求头 |
| `-d` | 发送请求体 |
| `-F` | 发送 multipart 表单字段或文件 |
| `-o` | 把响应体保存到文件 |
| `-L` | 跟随重定向 |

支持 `--json` 的 curl 版本可以简写 JSON 请求，但团队脚本要考虑实际安装版本与不同 Shell 的引号规则。

## 20. opacity、透明颜色和隐藏方式

### opacity

```css
.card {
  opacity: 0.5;
}
```

它让元素及其所有子内容一起透明。`opacity < 1` 还会创建新的堆叠上下文，可能影响 z-index 行为。

### 带 alpha 的颜色

```css
.card {
  background: rgb(0 0 0 / 0.5);
}
```

这里只让背景颜色半透明，文字和子元素不受影响。

### 隐藏方式对比

| 方法 | 是否可见 | 是否占据布局 | 是否可能拦截点击 | 辅助技术通常能否读取 |
| --- | :-: | :-: | :-: | :-: |
| `opacity: 0` | 否 | 是 | 是 | 是 |
| `visibility: hidden` | 否 | 是 | 否 | 通常否 |
| `display: none` | 否 | 否 | 否 | 否 |

因此不能只用 `opacity: 0` 隐藏交互控件。必要时还要管理 `pointer-events`、焦点顺序和无障碍状态。

## 22. 常见误区汇总

- **“Schema 就是数据库表”**：错误。Pydantic Schema 是 API 数据契约；SQLAlchemy Model 才映射数据库表。
- **“Schema 只能用于响应”**：错误。它也能描述创建和更新请求，并可作为 Python 对象传入函数。
- **“用了 SQLAlchemy 就不用学 SQL”**：错误。性能和一致性问题离不开 SQL、索引与事务。
- **“前后端分离替代 MVC”**：错误。它们讨论不同维度，可以结合使用。
- **“Vue 不需要 HTML 和 CSS”**：错误。Vue 在它们之上提供组件化与响应式能力。
- **“TypeScript interface 能验证后端响应”**：错误。interface 在运行时不存在。
- **“Pydantic 校验失败就是 400”**：不准确。FastAPI 默认请求验证错误通常是 422。
- **“opacity: 0 就等于元素不存在”**：错误。它仍占据布局并可能接收交互。
