## 1. Vue 3 的定位和作用

如果只使用原生 JavaScript，页面状态改变后需要手工寻找 DOM 并更新：

```ts
const count = 1
document.querySelector('#count')!.textContent = String(count)
```

Vue 的核心思路是：**开发者描述状态与页面之间的关系，Vue 负责在状态变化后更新 DOM。**

```vue
<script setup lang="ts">
import { ref } from 'vue'

const count = ref(1)
</script>

<template>
  <button type="button" @click="count++">
    当前数量：{{ count }}
  </button>
</template>
```

可以把 Vue 3 的核心能力概括为：

```text
响应式状态 + 声明式模板 + 组件化 + 组合式逻辑
```

Vue 不是用来替代 HTML、CSS 和 TypeScript，而是把它们组织成可维护的交互界面。

## 2. Vue 应用如何启动

Vite 项目的入口通常是 `src/main.ts`：

```ts
import { createApp } from 'vue'
import App from './App.vue'
import './assets/main.css'

createApp(App).mount('#app')
```

对应根目录 `index.html`：

```html
<div id="app"></div>
<script type="module" src="/src/main.ts"></script>
```

启动链路：

```text
index.html 中的 #app
        ↓
main.ts 创建 Vue 应用
        ↓
挂载根组件 App.vue
        ↓
App.vue 组合其他页面和组件
```

一个页面只能有一个根应用不是 Vue 3 的硬性规定，但常规 SPA 通常只创建一个应用实例。

## 3. 单文件组件 SFC

`.vue` 文件称为单文件组件，通常包含三部分：

```vue
<script setup lang="ts">
const title = 'TodoLab'
</script>

<template>
  <main class="page">
    <h1>{{ title }}</h1>
  </main>
</template>

<style scoped>
.page {
  max-width: 64rem;
  margin-inline: auto;
}
</style>
```

| 区域 | 职责 |
| --- | --- |
| `<script setup lang="ts">` | 状态、逻辑、导入和类型 |
| `<template>` | 基于 HTML 的页面结构 |
| `<style scoped>` | 当前组件的样式 |

`scoped` 会通过编译生成属性选择器来限制大部分样式作用范围，但不等于浏览器原生 Shadow DOM，也不代表样式永远不会受到继承或深层选择器影响。

## 4. `<script setup>`

`<script setup>` 是 Composition API 的常用写法。顶层声明可以直接在模板中使用：

```vue
<script setup lang="ts">
import TodoItem from '@/components/TodoItem.vue'

const pageTitle = '今日任务'
</script>

<template>
  <h1>{{ pageTitle }}</h1>
  <TodoItem />
</template>
```

其中 `defineProps`、`defineEmits`、`defineModel` 等是编译宏，不需要从 Vue 导入。

Vue 仍然支持 Options API：

```ts
export default {
  data() {
    return { count: 0 }
  },
  methods: {
    increment() {
      this.count++
    },
  },
}
```

新项目通常使用 Composition API 和 `<script setup>`。维护旧项目时则需要同时看懂 Options API。两种 API 都属于 Vue 3，不应把 Options API 说成已经失效。

## 5. 模板插值和表达式

文本插值：

```vue
<p>{{ userName }}</p>
<p>{{ completedCount }} / {{ todos.length }}</p>
```

模板中可以使用简单 JavaScript 表达式：

```vue
<p>{{ isLoggedIn ? '已登录' : '未登录' }}</p>
```

不要在模板里堆叠复杂业务逻辑。复杂计算应移入 `computed` 或普通函数，让模板保持可读。

插值默认会转义 HTML。只有明确需要渲染可信 HTML 时才考虑 `v-html`：

```vue
<div v-html="trustedHtml"></div>
```

不能把未经清洗的用户输入交给 `v-html`，否则可能产生 XSS 安全问题。

## 6. 常用模板指令

| 指令 | 用途 | 简写 |
| --- | --- | --- |
| `v-bind` | 绑定属性 | `:` |
| `v-on` | 监听事件 | `@` |
| `v-if` | 条件创建和销毁 | 无 |
| `v-show` | 使用 CSS 切换显示 | 无 |
| `v-for` | 根据集合重复渲染 | 无 |
| `v-model` | 表单双向绑定约定 | 无 |
| `v-html` | 插入 HTML | 无 |

属性和事件示例：

```vue
<button
  type="button"
  :disabled="isSaving"
  :class="{ active: selected }"
  @click="saveTodo"
>
  {{ isSaving ? '保存中…' : '保存' }}
</button>
```

事件修饰符：

```vue
<form @submit.prevent="submitForm">
  <input @keyup.enter="submitForm" />
</form>
```

`.prevent` 对应 `preventDefault()`，`.stop` 对应 `stopPropagation()`。修饰符应表达真实交互需要，不要机械添加。

## 7. `ref`：最常用的响应式状态

```ts
import { ref } from 'vue'

const count = ref(0)
const title = ref('学习 Vue')
const loading = ref(false)
```

在 TypeScript 中读取和修改需要 `.value`：

```ts
count.value++
title.value = '学习 Composition API'
```

模板会自动解包顶层 ref：

```vue
<p>{{ count }}</p>
<button @click="count++">增加</button>
```

`ref` 不只用于基本类型，也可以保存对象和数组：

```ts
interface Todo {
  id: number
  title: string
  completed: boolean
}

const todos = ref<Todo[]>([])

todos.value.push({
  id: 1,
  title: '学习 Vue',
  completed: false,
})
```

为了减少团队认知成本，业务项目可以优先使用 `ref` 表达需要整体替换或可能为空的状态。

## 8. `reactive`：响应式对象

```ts
import { reactive } from 'vue'

const form = reactive({
  title: '',
  priority: 'normal',
})

form.title = '阅读 Vue 文档'
```

`reactive` 只能直接接收对象类型。它适合字段经常被分别修改、且不需要频繁整体替换的对象。

常见错误是直接解构：

```ts
const { title } = form
```

此时 `title` 只是当前值，不再保持与 `form.title` 的响应式连接。需要解构为 ref 时使用：

```ts
import { toRefs } from 'vue'

const { title, priority } = toRefs(form)
```

简单选择原则：

```text
独立值、数组、可能为空、需要整体替换 → ref
一组紧密相关且按字段修改的对象       → reactive
```

二者不是性能优劣关系，重点是状态语义清楚。

## 9. `computed`：派生状态

```ts
import { computed, ref } from 'vue'

const todos = ref([
  { id: 1, title: '学习 Vue', completed: true },
  { id: 2, title: '学习 Router', completed: false },
])

const completedCount = computed(
  () => todos.value.filter((todo) => todo.completed).length,
)
```

`computed` 适合从现有响应式状态推导新值：

- 根据依赖自动更新；
- 依赖未变化时复用缓存；
- 默认应保持无副作用；
- 默认返回只读 ref。

如果一个值能够由其他状态算出，通常不应再单独保存一份，否则容易出现两份状态不一致。

## 10. `watch` 与 `watchEffect`

`watch` 明确指定要观察的来源：

```ts
import { ref, watch } from 'vue'

const keyword = ref('')

watch(keyword, (newKeyword, oldKeyword) => {
  console.log({ newKeyword, oldKeyword })
})
```

观察多个来源：

```ts
const page = ref(1)

watch([keyword, page], ([newKeyword, newPage]) => {
  console.log({ newKeyword, newPage })
})
```

观察对象中的某个字段：

```ts
watch(
  () => form.priority,
  (priority) => console.log(priority),
)
```

`watchEffect` 会立即运行，并自动追踪同步执行期间读取的响应式依赖：

```ts
import { watchEffect } from 'vue'

watchEffect(() => {
  document.title = `${completedCount.value} 个任务已完成`
})
```

使用区别：

| API | 适合场景 |
| --- | --- |
| `computed` | 产生新的派生值 |
| `watch` | 精确监听来源并执行副作用 |
| `watchEffect` | 依赖简单、允许自动收集的副作用 |

不要用 `watch` 维护本可由 `computed` 直接得到的数据。

异步请求要考虑旧请求覆盖新请求。可以在监听器中清理上一次任务：

```ts
watch(keyword, async (value, _oldValue, onCleanup) => {
  const controller = new AbortController()
  onCleanup(() => controller.abort())

  await fetch(`/api/v1/todos?q=${encodeURIComponent(value)}`, {
    signal: controller.signal,
  })
})
```

## 11. 条件渲染

```vue
<p v-if="loading">加载中…</p>
<p v-else-if="errorMessage">{{ errorMessage }}</p>
<TodoList v-else :todos="todos" />
```

`v-if` 与 `v-show`：

| 对比 | `v-if` | `v-show` |
| --- | --- | --- |
| 初始条件为假 | 不创建 DOM | 创建 DOM 后隐藏 |
| 切换成本 | 较高 | 较低 |
| 初始渲染成本 | 可能较低 | 始终渲染 |
| 适合 | 不常切换、条件复杂 | 高频显示隐藏 |

选择应基于切换频率和组件成本，不需要把其中一个绝对化为更优。

## 12. 列表渲染和 `key`

```vue
<ul>
  <li v-for="todo in todos" :key="todo.id">
    {{ todo.title }}
  </li>
</ul>
```

`key` 帮助 Vue 识别每个节点的稳定身份。增删、排序或包含输入框和子组件的列表应使用稳定业务 ID。

不推荐在会排序或增删的状态列表中使用数组下标：

```vue
<li v-for="(todo, index) in todos" :key="index">
```

因为位置改变后，同一个下标可能代表另一个业务对象，导致 DOM 状态或组件状态错误复用。

## 13. 表单与 `v-model`

```vue
<script setup lang="ts">
import { ref } from 'vue'

const title = ref('')
const completed = ref(false)
</script>

<template>
  <input v-model.trim="title" type="text" />
  <input v-model="completed" type="checkbox" />
</template>
```

常见修饰符：

| 修饰符 | 作用 |
| --- | --- |
| `.trim` | 去除文本首尾空白 |
| `.number` | 尝试转换为数字 |
| `.lazy` | 在 change 而不是 input 时同步 |

`v-model` 是绑定值与更新事件的语法约定，不应理解成绕过数据流的魔法。

原生输入框中，它相当于组合 `:value` 和 `@input`。组件上默认对应 `modelValue` 与 `update:modelValue`。

## 14. 组件拆分

组件适合在以下情况拆分：

- 可以独立命名；
- 有明确输入和输出；
- 被多处复用；
- 当前文件已经混合多个职责；
- 某部分逻辑需要单独维护或测试。

典型 Todo 页面：

```text
TodoView.vue
├─ TodoCreateForm.vue
├─ TodoFilterBar.vue
├─ TodoList.vue
│  └─ TodoItem.vue
└─ TodoEmptyState.vue
```

不要把每个 `<div>` 都拆成组件。组件边界应围绕业务职责，而不是单纯追求文件数量。

## 15. Props：父组件向子组件传数据

```vue
<!-- TodoItem.vue -->
<script setup lang="ts">
interface Todo {
  id: number
  title: string
  completed: boolean
}

const props = defineProps<{
  todo: Todo
  disabled?: boolean
}>()
</script>

<template>
  <article :class="{ completed: props.todo.completed }">
    {{ props.todo.title }}
  </article>
</template>
```

父组件传入：

```vue
<TodoItem :todo="todo" :disabled="isSaving" />
```

Props 在子组件中是只读输入。子组件不应直接修改父组件拥有的状态。

## 16. Emits：子组件向父组件报告事件

```vue
<!-- TodoItem.vue -->
<script setup lang="ts">
interface Todo {
  id: number
  title: string
  completed: boolean
}

const props = defineProps<{
  todo: Todo
}>()

const emit = defineEmits<{
  toggle: [id: number]
  remove: [id: number]
}>()
</script>

<template>
  <article>
    <button type="button" @click="emit('toggle', props.todo.id)">
      切换状态
    </button>
    <button type="button" @click="emit('remove', props.todo.id)">
      删除
    </button>
  </article>
</template>
```

父组件监听：

```vue
<TodoItem
  :todo="todo"
  @toggle="toggleTodo"
  @remove="removeTodo"
/>
```

核心数据流：

```text
父组件状态
   ↓ props
子组件展示
   ↓ emits
父组件决定如何更新状态
```

这称为单向数据流。它让状态的拥有者和修改位置更容易追踪。

## 17. 组件 `v-model`

传统写法：

```vue
<script setup lang="ts">
const props = defineProps<{
  modelValue: string
}>()

const emit = defineEmits<{
  'update:modelValue': [value: string]
}>()
</script>

<template>
  <input
    :value="props.modelValue"
    @input="emit('update:modelValue', ($event.target as HTMLInputElement).value)"
  />
</template>
```

父组件：

```vue
<TodoTitleInput v-model="title" />
```

较新的 Vue 3 项目可以使用 `defineModel` 简化组件实现，但应先确认项目 Vue 版本：

```vue
<script setup lang="ts">
const model = defineModel<string>({ required: true })
</script>

<template>
  <input v-model="model" />
</template>
```

面试中应能说明底层约定，而不只是说 `v-model` 是双向绑定。

## 18. Slots：父组件提供结构内容

子组件定义插槽：

```vue
<!-- BaseCard.vue -->
<template>
  <section class="card">
    <header><slot name="header" /></header>
    <div><slot /></div>
  </section>
</template>
```

父组件填充：

```vue
<BaseCard>
  <template #header>今日任务</template>
  <p>还有 3 项未完成</p>
</BaseCard>
```

简单区分：

```text
Props 传数据
Emits 传事件
Slots 传一段模板结构
```

## 19. 生命周期

常用生命周期：

```ts
import { onBeforeUnmount, onMounted, onUpdated } from 'vue'

onMounted(() => {
  window.addEventListener('resize', handleResize)
})

onUpdated(() => {
  console.log('组件 DOM 已因响应式更新而变化')
})

onBeforeUnmount(() => {
  window.removeEventListener('resize', handleResize)
})
```

| 生命周期 | 常见用途 |
| --- | --- |
| `onMounted` | 访问 DOM、启动依赖浏览器环境的第三方库 |
| `onUpdated` | DOM 更新后处理，通常应谨慎使用 |
| `onBeforeUnmount` | 清理监听器、定时器、订阅和外部实例 |

不要把所有请求都机械放入 `onMounted`。路由参数变化、筛选条件变化或服务端渲染场景可能需要其他数据加载策略。

## 20. 模板引用与 `nextTick`

需要直接访问 DOM 时使用模板引用：

```vue
<script setup lang="ts">
import { nextTick, ref } from 'vue'

const inputElement = ref<HTMLInputElement | null>(null)
const visible = ref(false)

async function showAndFocus() {
  visible.value = true
  await nextTick()
  inputElement.value?.focus()
}
</script>

<template>
  <input v-if="visible" ref="inputElement" />
  <button type="button" @click="showAndFocus">显示并聚焦</button>
</template>
```

Vue 会批量安排 DOM 更新，所以状态刚修改时 DOM 不一定已经同步完成。`nextTick` 用于等待本轮 DOM 更新。

模板引用应只用于焦点、尺寸、第三方 DOM 库等必要场景，不要退回到大量手工操作 DOM。

## 21. 异步请求的基本状态

远程数据通常至少包含四种状态：

```text
data + loading + error + empty
```

```ts
import { onMounted, ref } from 'vue'

interface Todo {
  id: number
  title: string
  completed: boolean
}

const todos = ref<Todo[]>([])
const loading = ref(false)
const errorMessage = ref('')

async function loadTodos() {
  loading.value = true
  errorMessage.value = ''

  try {
    const response = await fetch('/api/v1/todos')

    if (!response.ok) {
      throw new Error(`请求失败：${response.status}`)
    }

    todos.value = (await response.json()) as Todo[]
  } catch (error) {
    errorMessage.value = error instanceof Error ? error.message : '未知错误'
  } finally {
    loading.value = false
  }
}

onMounted(loadTodos)
```

`as Todo[]` 只提供 TypeScript 编译期提示，不会验证运行时 JSON。重要或不可信数据仍应使用运行时 Schema 校验。

## 22. 组合式函数 Composable

组合式函数用于复用有状态逻辑，命名通常以 `use` 开头：

```ts
// src/composables/useTodos.ts
import { computed, ref } from 'vue'

export interface Todo {
  id: number
  title: string
  completed: boolean
}

export function useTodos() {
  const todos = ref<Todo[]>([])

  const remainingCount = computed(
    () => todos.value.filter((todo) => !todo.completed).length,
  )

  function addTodo(title: string) {
    todos.value.push({
      id: Date.now(),
      title,
      completed: false,
    })
  }

  function toggleTodo(id: number) {
    const todo = todos.value.find((item) => item.id === id)
    if (todo) todo.completed = !todo.completed
  }

  return {
    todos,
    remainingCount,
    addTodo,
    toggleTodo,
  }
}
```

组件使用：

```ts
const { todos, remainingCount, addTodo, toggleTodo } = useTodos()
```

Composable 复用的是逻辑和状态组织方式；组件复用的是 UI 与交互。它不是把所有函数统一搬进 `composables/`。

每次调用 composable 默认会创建独立状态。模块顶层状态或 Pinia 才更适合跨组件共享，本课程下一阶段会专门讲解。

## 23. Provide 与 Inject

多层组件之间传递上下文时可以使用 `provide` 和 `inject`：

```ts
// 上层组件
import { provide, readonly, ref } from 'vue'

const theme = ref<'light' | 'dark'>('light')
provide('theme', readonly(theme))
```

```ts
// 深层子组件
import { inject } from 'vue'

const theme = inject('theme', 'light')
```

它适合主题、表单上下文、组件库内部协作等场景。普通父子组件仍优先使用 Props 和 Emits；复杂的全局业务状态通常交给 Pinia。

大型 TypeScript 项目应使用 `InjectionKey` 提供更可靠的类型约束，避免到处使用字符串键。

## 24. Vue 的更新机制

概念链路：

```text
读取 ref / reactive
        ↓
Vue 记录当前渲染依赖
        ↓
状态发生变化
        ↓
相关组件进入更新队列
        ↓
批量计算新的虚拟 DOM
        ↓
对比并更新必要的真实 DOM
```

面试中不必把 Vue 描述成“数据一变就重新创建整个页面”。Vue 会追踪响应式依赖，并通过调度和虚拟 DOM 更新相关部分。

Vue 3 的响应式对象主要基于 `Proxy`，`ref` 则通过带 `.value` 的对象统一保存值并接入依赖追踪。

## 25. 一套完整的 Todo 组件写法

```vue
<script setup lang="ts">
import { computed, ref } from 'vue'

interface Todo {
  id: number
  title: string
  completed: boolean
}

const title = ref('')
const todos = ref<Todo[]>([])

const remainingCount = computed(
  () => todos.value.filter((todo) => !todo.completed).length,
)

function addTodo() {
  const normalizedTitle = title.value.trim()
  if (!normalizedTitle) return

  todos.value.push({
    id: Date.now(),
    title: normalizedTitle,
    completed: false,
  })

  title.value = ''
}

function removeTodo(id: number) {
  todos.value = todos.value.filter((todo) => todo.id !== id)
}
</script>

<template>
  <main class="todo-page">
    <h1>TodoLab</h1>

    <form class="todo-form" @submit.prevent="addTodo">
      <label for="todo-title">新任务</label>
      <input
        id="todo-title"
        v-model="title"
        type="text"
        maxlength="100"
        placeholder="输入任务标题"
      />
      <button type="submit" :disabled="!title.trim()">添加</button>
    </form>

    <p aria-live="polite">剩余 {{ remainingCount }} 项</p>

    <ul v-if="todos.length">
      <li v-for="todo in todos" :key="todo.id">
        <label>
          <input v-model="todo.completed" type="checkbox" />
          <span :class="{ completed: todo.completed }">
            {{ todo.title }}
          </span>
        </label>
        <button type="button" @click="removeTodo(todo.id)">删除</button>
      </li>
    </ul>

    <p v-else>暂无任务</p>
  </main>
</template>

<style scoped>
.todo-page {
  width: min(100% - 2rem, 42rem);
  margin-inline: auto;
}

.todo-form {
  display: grid;
  gap: 0.75rem;
}

.completed {
  color: #64748b;
  text-decoration: line-through;
}
</style>
```

这段代码已经覆盖 Vue 日常开发最常见的主线：

```text
ref → computed → 事件函数 → v-model → v-if → v-for → class 绑定
```

## 26. 常见项目目录

```text
src/
├─ api/             接口请求和响应适配
├─ assets/          样式、图片、字体
├─ components/      可复用 UI 或业务组件
├─ composables/     可复用组合式逻辑
├─ router/          路由配置和守卫
├─ stores/          Pinia 全局状态
├─ types/           跨模块共享类型
├─ views/           路由级页面
├─ App.vue
└─ main.ts
```

推荐依赖方向：

```text
View
 ├─ Components
 ├─ Composables
 ├─ Stores
 └─ API
```

不要让基础 UI 组件反向依赖某个具体页面。接口请求也不应散落在所有按钮事件中，应逐步收口到 API 层或对应的业务逻辑层。

## 27. 常见错误与准确理解

### 修改普通变量后页面不更新

```ts
let count = 0
count++
```

普通局部变量不是响应式状态。需要参与模板更新时使用 `ref` 或 `reactive`。

### 在脚本中忘记 `.value`

```ts
const count = ref(0)
count++ // 错误
count.value++ // 正确
```

### 直接修改 Props

子组件应通过 emits 通知父组件，或创建自己的本地状态，不应直接写入 Props。

### 使用数组下标作为可变列表 key

会导致节点与业务对象身份错位。优先使用数据库 ID 或稳定生成的 ID。

### 用 watch 保存派生值

可以从现有状态计算出的值优先使用 `computed`，减少同步问题。

### 把所有状态都放入全局 Store

输入框、弹窗开关等局部状态通常留在组件中。只有跨页面共享、多个远距离组件共同依赖或需要持久化协调的业务状态才适合 Pinia。

### 以为 TypeScript 已经校验接口响应

TypeScript 类型在运行时不存在。后端契约错误仍可能导致前端运行时问题。

### 过度依赖生命周期

很多逻辑可以由 computed、watch、事件和 composable 更直接地表达。生命周期主要负责组件与外部环境之间的建立和清理。

## 31. 面试表达速记

### Vue 3 的核心价值

> Vue 3 通过响应式系统追踪状态依赖，使用声明式模板描述界面，并以组件化方式组织 UI。状态变化后，Vue 会调度相关组件更新，而不是要求开发者手工维护每个 DOM 节点。

### Composition API

> Composition API 允许按业务能力组织状态、派生值、副作用和函数，同一功能不必分散在 data、computed、methods 等选项中，也便于提取 composable 复用逻辑。`<script setup>` 是它在单文件组件中的常用简化写法。

### `ref` 与 `reactive`

> `ref` 可以包装任意值，通过 `.value` 访问，适合独立状态、数组和需要整体替换的对象。`reactive` 直接代理对象，适合按字段修改的一组状态。两者都能实现响应式，选择重点在状态语义与团队一致性。

### `computed` 与 `watch`

> `computed` 用来声明派生值，具备依赖追踪和缓存，应该尽量保持无副作用。`watch` 用来观察明确来源并执行请求、存储或日志等副作用。能计算出来的数据优先使用 computed。

### Props 与 Emits

> Vue 组件遵循单向数据流。父组件通过 Props 下发数据，子组件通过 Emits 报告事件，由状态拥有者决定如何更新。这样可以避免多个组件随意修改同一份状态。

### `v-model`

> 原生表单上的 v-model 是值绑定与输入事件的语法简化。组件上的默认约定是 `modelValue` Prop 和 `update:modelValue` 事件。较新版本还可以使用 `defineModel` 简化声明。

### `key`

> key 表示列表节点的稳定身份，帮助 Vue 在更新时正确复用和移动 DOM 或组件实例。可变列表使用数组下标会让位置替代业务身份，因此应优先使用稳定 ID。

### 生命周期

> 生命周期用于处理组件与外部环境的连接，例如挂载后访问 DOM，以及卸载前清理事件监听、定时器和第三方实例。普通派生关系应优先使用 computed，条件副作用使用 watch，而不是全部放进生命周期。

### Composable

> Composable 是使用 Composition API 封装的可复用有状态逻辑，通常以 use 开头。它复用逻辑，不直接决定 UI；组件负责界面结构和交互呈现。

### 虚拟 DOM 与更新

> Vue 渲染期间记录响应式依赖，状态变化后把相关组件加入更新队列，再比较新旧虚拟 DOM 并更新必要的真实 DOM。它不是每次都重建整个页面。

## 32. 阅读 Vue 代码的固定顺序

接手项目或阅读 AI 代码时，按以下顺序理解：

```text
1. 组件的 Props 和 Emits
2. 本地 ref / reactive 状态
3. computed 派生状态
4. watch 与生命周期副作用
5. 事件处理函数
6. template 的条件、循环和组件关系
7. API、Store 与 Composable 依赖
8. loading、error、empty 等边界状态
```

这个顺序能快速回答三个关键问题：状态属于谁、状态在哪里改变、页面如何随状态变化。
